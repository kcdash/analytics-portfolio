# Maple & Main synthetic data

Maple & Main is a fictional Canadian omnichannel retailer with a loyalty program. Every table here is generated by
`generate_maple_main.py` from a fixed seed. Nothing in it comes from a real customer, client or employer.

- **Window:** 2023-11-06 to 2026-11-01 (156 weeks), amounts in CAD
- **Full size:** about 200,000 customers; written to `data/full/` (not committed, regenerate locally)
- **Sample:** `data/sample/` is the same generator at 1% scale, committed so the code runs straight from a clone

```
python data/generate_maple_main.py                               # full data -> data/full/
python data/generate_maple_main.py --scale 0.01 --out data/sample
python data/generate_maple_main.py --no-issues                   # without planted data-quality issues
```

## Tables

| Table | Grain | Key columns |
|---|---|---|
| `customers` | one row per loyalty member | `customer_id`, `join_date`, `province`, `postal_fsa`, `age_band`, `loyalty_tier`, `acquisition_channel`, `email_opt_in`, `sms_opt_in`, `home_store_id` |
| `transactions` | one row per order | `order_id`, `customer_id`, `order_date`, `channel` (Store, Web, App), `store_id`, `gross_amount`, `discount_amount`, `net_amount`, `points_earned`, `points_redeemed` |
| `order_items` | one row per order line | `order_id`, `line_no`, `sku`, `quantity`, `unit_price`, `promo_flag` |
| `products` | one row per SKU | `sku`, `category`, `subcategory`, `brand`, `list_price`, `unit_cost` |
| `stores` | one row per store | `store_id`, `province`, `city`, `store_format`, `open_date` |
| `campaigns` | one row per CRM campaign | `campaign_id`, `channel` (Email, SMS, Direct Mail), `offer`, `start_date`, `end_date`, `cost_per_contact_cad`, `audience_size`, `treated_size` |
| `campaign_contacts` | campaign x customer | `treatment_group` (Treatment, Holdout), `sent_flag`, `opened_flag`, `clicked_flag`, `responded_flag` (order within 14 days) |
| `media_spend_weekly` | week x media channel | `week_start`, `channel` (TV, Paid Search, Paid Social, Display, Flyer, Email), `spend_cad`, `impressions` |
| `web_activity_monthly` | customer x month with activity | `sessions`, `page_views`, `cart_adds`, `abandoned_carts` |
| `service_contacts` | one row per service contact | `contact_date`, `contact_channel`, `reason`, `resolved_flag`, `csat_score` |
| `loyalty_events` | one row per loyalty event | `event_type` (ENROL, TIER_CHANGE, REDEMPTION, POINTS_EXPIRY), `tier_from`, `tier_to`, `points` |
| `prospects` | one row per prospect | lead source, demographics, `web_visits_30d`, `converted_flag`, `converted_customer_id` |

## Signals built into the data

- **Churn:** each customer has a hidden churn date driven by engagement, tier, acquisition channel, email opt-in and service friction. Browsing fades and complaints rise before it.
- **Campaign uplift:** every campaign has a 10% holdout. Uplift is largest for mid-engagement customers and negative for a small low-engagement SMS group.
- **Media response:** weekly orders respond to six media channels through adstock and saturation curves.
- **Seasonality:** holiday and back-to-school peaks, plus category-level seasonality (outdoor in spring, toys and electronics in Q4).
- **Acquisition:** prospect conversion depends on lead source, web visits, distance to store, income and email engagement.

The exact parameters are saved in `truth/ground_truth.json` and `truth/customer_truth.csv`, so each model can be checked
against the mechanism that produced the data. Models never read the truth files as inputs.

## Planted data-quality issues

The raw tables include deliberate defects for the QC and EDA projects: duplicate customers and orders, missing postal
codes, provinces spelled out instead of coded, mixed date formats, basket outliers, negative amounts, a tier-code change
in March 2025 and missing media weeks. Counts are logged in `truth/ground_truth.json`.
